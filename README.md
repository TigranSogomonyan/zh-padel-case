# ZH — конфигуратор кожаного чехла для падел-ракетки

Витрина: **https://tigransogomonyan.github.io/zh-padel-case/**

Здесь лежит только собранная страница. Исходник — `index.html` в рабочей
папке проекта; отсюда его не правят, правки затрутся следующей выкладкой.

`index.html` в этом репозитории — один самодостаточный файл: разметка, стили,
вся 3D-логика, three.js r128 и шрифты вшиты внутрь. Внешних запросов у
страницы нет вовсе, поэтому она открывается с любого статического хоста и
работает без видеокарты — чехол рисует свой растеризатор на canvas 2D.

## Чем отличается от локальной версии

Собрано ключом `--static`: приёмник заявок (`/api/orders`, Laravel из `api/`)
рядом с этой страницей не стоит, и отправка выключена. Форма про это честно
говорит и кладёт заявку в буфер обмена. Кнопка «Save preview» осталась —
статический хост отдавать файлы умеет.

Чтобы заявки уходили, нужен адрес поднятого приёмника: либо вписать его в
`ORDER_ENDPOINT` в `index.html` проекта, либо задать `window.__ZH_ORDER_ENDPOINT`
до загрузки страницы.

## Обновить витрину

Из рабочей папки проекта:

    npm run deploy

Скрипт пересобирает страницу из свежего `index.html` и отправляет её сюда.
GitHub Pages подхватывает новый коммит сам, обычно за минуту.

## Автоматическая проверка витрины

Ветка с проверками добавляет браузерный smoke-тест готового `index.html` без
изменения собранной страницы. Он открывает сайт в Chromium на двух размерах
экрана (1440 × 900 и 390 × 844), проверяет загрузку, наличие контента,
canvas для 3D и отсутствие необработанных ошибок JavaScript.

Запуск локально при наличии Node.js:

```bash
npm install
npx playwright install chromium
npm run test:smoke
```

Результат: `artifacts/zh-desktop.png`, `artifacts/zh-mobile.png` и
`artifacts/report.json`. Показатель горизонтального переполнения
записывается для диагностики, но пока не блокирует проверку.

GitHub Actions запускает тест при pull request и push в `main`;
скриншоты доступны в артефакте `zh-browser-smoke` соответствующего запуска.

Это **smoke-тест**, а не полная проверка удобства управления 3D и не
проверка отправки заказа. Для последней нужен работающий Laravel API,
которого в статической витрине сейчас нет.
