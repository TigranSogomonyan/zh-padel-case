# Готовый промпт для Codex — ZH, первая продуктовая итерация

Контекст: проект **ZH — Padel Racket Case**, премиальный сайт-конфигуратор кожаного чехла для падел-ракетки. Репозиторий с опубликованной сборкой: https://github.com/TigranSogomonyan/zh-padel-case. Публичная витрина: https://tigransogomonyan.github.io/zh-padel-case/. Черновой PR с тестами и аудитом: https://github.com/TigranSogomonyan/zh-padel-case/pull/1.

**Важно:** GitHub-репозиторий содержит *сгенерированный* standalone `index.html`, а **оригинальные исходники**, Laravel `api/`, сервер и скрипты сборки — в локальной рабочей папке, которую я открываю на компьютере. Правь именно исходный проект. Сборку проверяй через существующий пайплайн. Не коммить секреты и токены.

## Твоя задача

1. Изучи структуру *этой* локальной папки (особенно `README`, `HANDOFF`, `index.html`, `package.json`, скрипт сборки/деплоя, материалы `api/`), выясни точную цепочку **исходники → build → GitHub Pages**. Прочти UX-аудит `docs/AUDIT_2026-11-03.md` и PR №1 в GitHub.
2. Проведи предметную проверку текущего UI: desktop 1440 px; mobile 390, 375, 320 px. Не меняй визуальную концепцию вслепую. Сначала зафиксируй скриншоты и состояния.
3. Реализуй небольшую **первую итерацию UX**, не переписывая 3D:
   - В блоке `IMPRESSION POSITION` свяжи визуальные подписи **ACROSS** и **ALONG** с соответствующими `input[type=range]` через правильные `label`/`aria-labelledby`; проверь клавиатурное управление. Если значения отражают миллиметры, сделай их понятными для screen reader.
   - На мобильной странице обеспечь **быстрый переход к форме заказа из зоны конфигуратора**. Выбери аккуратное решение (кнопка-якорь или ненавязчивая закреплённая CTA) с учётом safe-area, открытой клавиатуры и отсутствия перекрытий. Сохрани премиальную эстетику.
   - Для статической GitHub Pages-версии **ясно обозначь отсутствие отправки через API**: пользователь должен видеть, что происходит копирование конфигурации, а не подтверждение заказа. Не называй успешным действием отправку без серверного ответа.
   - Сохрани крупную 3D-модель и все рабочие настройки, не добавляй лишние модальные окна и навязчивую анимацию.
4. Прогони и при необходимости адаптируй имеющиеся browser smoke tests из PR №1. На всех ширинах убедись: нет ошибок JavaScript/горизонтального скролла; работает смена кожи, ввод инициалов, изменение ракурса и скачивание превью. Проверь, что два range-поля теперь имеют доступные имена. Отдельно проверь режим без WebGL.
5. Подготовь отчёт: что изменил, какие файлы затронуты, как запустить тесты, какие вопросы ещё не решены, какие скриншоты до/после получены. Создай **отдельную ветку и PR** для изменений в исходном проекте, если он является репозиторием. Если исходная папка не под Git — объясни и не создавай дубликат проекта без моего согласия.

## Запреты и границы

- Не переписывай и не оптимизируй собственный software renderer `canvas 2D` и его геометрию в этой итерации.
- Не меняй размеры чехла **284 × 497 × 46 мм**, цвета, систему монограммы и поведение камер без конкретной необходимости.
- Не деплой в продакшен, не объединяй PR в `main`, не отправляй реальные заявки и сообщения в Telegram.
- Не выдумывай цены, сроки изготовления, наличие товара или историю бренда.
- Если какая-то функция в исходной папке отсутствует — опиши найденный факт, не создавая вымышленную архитектуру.
- Выполни максимально возможный объём работы автономно и предложи результат на ревью, а не останавливайся после общего плана.

## Готово, когда

- Исходники правильно собираются, изменения воспроизводятся при деплое.
- В обоих ползунках есть корректное доступное имя.
- На мобильном экране до заказа можно перейти одним действием.
- Статическая витрина не имитирует успешно отправленный заказ.
- Рендер и основные интерактивные функции сохранились.
- Тесты на 1440 / 390 / 375 / 320 px успешны либо конкретные существующие дефекты задокументированы.
- Я получаю PR и краткий отчёт с доказательствами.
