# ZH — аудит интерфейса и план улучшений (03.11.2026)

## Основание и границы

- Осмотрены настоящие скриншоты собранной страницы, созданные GitHub Actions: desktop **1440 × 2189 px** и mobile **390 × 4277 px**.
- Проверены результаты smoke-теста страницы на viewport 1440 × 900 и 390 × 844. В обоих режимах найден один `canvas`, нет необработанных ошибок JavaScript и горизонтального переполнения.
- Собранная версия хранится в корневом `index.html`. **Её нельзя считать редактируемым исходником**: повторный `npm run deploy` может заменить файл.
- Рекомендации по интерфейсу ниже — визуальный аудит снимков, не подтверждённое исследование пользователей. Backend Laravel здесь не развернут.

## Находки по приоритету

### P0 — ясный путь к заявке

**Наблюдение.** На мобильном скриншоте конфигуратор, восемь информационных карточек и спецификация идут перед полями заявки; CTA оказывается в самом конце очень длинной страницы. На статической витрине приёмник заявок отключён: согласно README, параметры копируются в буфер обмена.

**Решение в исходном проекте.**
1. Добавить понятную кнопку перехода к секции заказа рядом с конфигуратором и, при необходимости, липкую мобильную CTA с учётом safe-area.
2. Чётко различать реальные действия: *Send request* только при работающем API, иначе *Copy configuration* и прямое пояснение, куда отправить скопированные данные.
3. В форме показать результат отправки, ошибки сети и повторную попытку. Не делать вид, будто заказ принят, если API недоступен.

**Приёмка.** На мобильном экране пользователь может перейти к заказу из области конфигуратора за одно действие; ни одна кнопка не сообщает об успешной отправке без подтверждения сервера.

### P0 — доступные подписи двух ползунков

**Наблюдение.** Автоматический анализ элементов нашёл **2 поля `input[type="range"]` без вычисляемого доступного имени**. На изображении они расположены в блоке `IMPRESSION POSITION` и визуально подписаны `ACROSS` / `ALONG`. Остальные кнопки, включая 6 цветов кожи, имеют имена; `<html lang>` и meta viewport присутствуют.

**Решение в исходном проекте.** Связать обе подписи с соответствующими `input` через `label[for]` / `id` либо `aria-labelledby`. Добавить информативные `aria-valuetext` для положения в миллиметрах (если актуально), проверить клавиатуру и screen reader.

**Приёмка.** Оба range-инпута имеют понятное доступное имя и меняются клавишами со стрелками; аудит не выдаёт безымянных полей.

### P1 — мобильные цели нажатия и читаемость

**Наблюдение.** Мобильный интерфейс качественно помещается в 390 px, но вкладки камеры, выбор шрифта и микроподписи имеют очень плотную композицию. В особенности табы `THREE-QUARTER / FRONT / PROFILE / BACK` выглядят невысокими для касания.

**Решение.** Проверить реальные bounding rect интерактивных элементов на 390 / 375 / 320 px. Для основных сенсорных контролов ориентироваться на высоту зоны касания не менее 44 px; увеличить шрифт служебных подписей там, где он плохо читается, не жертвуя плотностью премиального дизайна.

**Приёмка.** Все основные действия легко нажимаются пальцем; горизонтального скролла нет; на iPhone с увеличенным текстом форма не обрезается.

### P1 — объяснить продукт раньше

**Наблюдение.** Главный заголовок — `Your initials, pressed into the hide`: выразительный, но не называет продукт. Название `PADEL RACKET CASE · MADE TO ORDER` набрано мелко в шапке. Цена и срок изготовления не указаны: форма обещает, что их сообщат в ответе.

**Решение.** Оставить художественный заголовок, но рядом добавить понятное описание `Made-to-order leather padel racket case` и честный статус цены / сроков. Если цифры ещё не известны, не выдумывать их.

**Приёмка.** Без прокрутки понятно, что именно настраивается, что персонализируется и что произойдёт после нажатия CTA.

### P2 — визуальная презентация изделия

**Наблюдение.** У модели приятная фактура кожи; есть 6 цветов, 4 угла камеры, ремень, тиснение. Однако реальные детали материала и креплений лучше показать дополнительно.

**Решение.** Добавить 2–3 компактных предметных детали (зерно кожи, шов, D-кольца/ремень) из подлинных фотографий или точных рендеров. Не заменять основной 3D-конфигуратор статичной галереей.

### P2 — непрерывность тестирования

- Сохранять тесты для desktop/mobile, изображения и отчёт CI.
- Проверять, что выбор `Burgundy` изменяет **само изображение `canvas`**, а не только состояние кнопки.
- В будущем тестировать ввод инициалов (до трёх символов), переключение видов, Copy Spec, Save Preview и режим с недоступным API.
- Интеграционные проверки отправки выполнять только в безопасном тестовом окружении Laravel; не создавать реальные заявки в продакшене.

## Что нельзя ломать

- Встроенный software rasterizer на Canvas 2D без зависимости от WebGL.
- Существующие цвета, настройки тиснения, размеры изделия 284 × 497 × 46 мм, выбор ремня и виды камеры.
- Работа статической витрины на GitHub Pages.
- Команда `npm run deploy` и исходная структура сборки.

## Технический блокер

В этом репозитории отсутствует полноценная исходная рабочая папка, описанная в `portfolio-case/case.md` (`api/`, `server.js`, скрипты сборки и файлы исходной сцены). Для правок интерфейса и заказа на ПК необходимо открыть **оригинальную локальную папку** в Codex. Не патчить корневой сгенерированный `index.html` как постоянное решение.

Скриншоты и результаты: GitHub Actions → `ZH static page smoke tests` → артефакт `zh-browser-smoke`.
