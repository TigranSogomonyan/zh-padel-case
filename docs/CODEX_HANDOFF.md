## Первое действие на ПК

Открой **исходную локальную папку ZH** в Codex. Проверь наличие оригинального `index.html`, `server.js`, `api/`, scripts/deploy и `files/HANDOFF.md` (точные пути могут отличаться). Не начинай с клонирования одной лишь GitHub Pages-витрины: её `index.html` — собранный монолит, который перезаписывается при деплое.

## Задача Codex — первый небольшой PR из исходников

> Изучи исходную папку ZH и документацию. Не нарушай работу canvas 2D и конфигуратора. Исправь доступные имена двух range-ползунков `ACROSS` и `ALONG` в блоке `IMPRESSION POSITION`. Добавь удобный переход к секции заказа с мобильного конфигуратора и проясни статический режим, когда API не подключён: кнопка должна отражать реальное действие, а пользователь — видеть объяснение. Сохрани премиальную тёмную стилистику и отсутствие горизонтального переполнения. Проверь desktop 1440 px и mobile 390 px, а также промежуточные 375/320 px. Прогони имеющиеся тесты и подготовь отдельный PR; не сливай в `main` без согласования. Не редактируй вручную опубликованный собранный `index.html` без изменения исходника.

## Следующий этап, но не смешивать с первым PR

1. Уточнить и показать честную информацию о цене, индивидуальном изготовлении и сроках.
2. Подключить Laravel API на стабильном хостинге с корректной конфигурацией CORS, HTTPS, ограничением запросов, валидацией и защитой персональных данных.
3. Проверить отказ сети и гарантировать, что интерфейс не сообщает об успешной заявке до ответа сервера.
4. Перенести браузерные тесты в исходный репозиторий или интегрировать их в текущую команду деплоя.

## Проверенные размеры и задачи по удобству нажатий (03.11.2026)

Последний автоматический аудит на 1440, 390, 375 и 320 px подтвердил работу Canvas 2D, переключения кожи Burgundy, инициалов ZH и вида Back при отсутствии горизонтального переполнения. По измерениям настоящего DOM:

| Ширина | Круговые переключатели кожи | Переключатели ракурса |
| --- | --- | --- |
| 390 px | 42 × 42 px | примерно 32 px по высоте |
| 375 px | 39 × 39 px | требуется проверить видимость и фактическую hit-area |
| 320 px | 30 × 30 px | требуется проверить видимость и фактическую hit-area |

**Приоритет первой реализации:** увеличить зоны касания 6 переключателей кожи и 4 видов камеры до ориентира не менее 44 × 44 CSS px там, где возможно. Можно увеличить невидимую область кнопки, а не видимый цветовой круг. На 320 px допустима продуманная перестройка сетки / перенос на вторую строку: главное — не допустить перекрытий и горизонтальной прокрутки. Проверить клавиатуру и фокус.

GitHub Actions публикует сводную таблицу нарушений в job summary; подробные размеры и скриншоты — в артефакте `zh-browser-smoke`.

## Критерии готовности

- CSS и JS берутся из корректных исходников, изменения воспроизводятся командой сборки.
- Оба range-инпута имеют accessible name.
- На мобильных ширинах проверены 6 цветовых кнопок и 4 переключателя ракурса; целевые hit-area достаточно велики для пальца, смежные зоны не пересекаются.
- Можно перейти к заказу без длительной прокрутки по мобильной странице.
- Нет ложной отправки заявки на GitHub Pages.
- Рендер, смена кожи, режим без WebGL и сохранение превью работают.
- CI проходит и сохраняет скриншоты.
